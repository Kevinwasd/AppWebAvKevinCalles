# 2026-10-15 — PoliMusic (app de música en ASP Clásico + SQL Server)

## Qué se construyó
Aplicación web completa tipo Spotify en **ASP Clásico (VBScript)**, tema oscuro con
color principal **turquesa** (`#14b8a6`), base de datos **SQL Server** `BDD_PoliMusic`.

- 41 archivos `.asp` (22 páginas + 12 includes + 10 vistas).
- Autenticación: `login.asp`, `register.asp`, `logout.asp`, `profile.asp`.
- Shell principal `home.asp` con navegación por AJAX (`api_view.asp`) para que el
  audio **no se corte** al cambiar de sección.
- Reproductor propio (`assets/js/player.js`): cola, aleatorio, repetición, seek,
  volumen, atajos de teclado, Media Session y contador de reproducciones.
- CRUD por rol: admin (`admin_*.asp`) para canciones/usuarios/artistas/álbumes/
  playlists; usuario normal con CRUD de sus propias playlists.
- Subida de archivos multipart sin componentes externos (`includes/upload.asp`).
- SHA-1 implementado en VBScript puro (`includes/sha1.asp`).
- Marcadores SVG dinámicos (`placeholder.asp`) cuando falta una imagen.

## Decisiones técnicas clave (importantes para el futuro)
1. **Todas las páginas ASP viven en la raíz de la aplicación** (no en `admin/` ni
   `api/`). En ASP clásico `#include file="../..."` exige `enableParentPaths`,
   que está **deshabilitado por omisión** en IIS (`IIS_schema.xml`,
   `defaultValue="false"`). Con las páginas en la raíz las inclusiones son siempre
   `includes/...` y la app funciona en cualquier IIS sin tocar la configuración.
2. **`web.config` no declara la sección `<asp>`**: no está garantizado que esté
   delegada a nivel de sitio y un error 500.19 dejaría la app inservible.
   `deploy.ps1` configura `enableParentPaths` y `maxRequestEntityAllowed` con appcmd.
3. `Param()` consulta primero la **QueryString**: en peticiones multipart no se
   puede tocar `Request.Form` después de `Request.BinaryRead` (error ASP 0106).
4. `DbInsert()` usa `SET NOCOUNT ON` para que el primer conjunto de resultados del
   lote sea siempre el `SELECT SCOPE_IDENTITY()`.
5. Los archivos fuente son **ASCII puro**; los acentos van como entidades HTML
   (`&iquest;`, `&oacute;`) y en JS como `\u00bf`. Evita problemas de codepage.

# 2026-10-15 (tarde) — Primer despliegue en IIS y corrección de errores

## Qué pasó
El usuario ejecutó `desplegar.bat`. La aplicación quedó copiada en
`C:\inetpub\wwwroot\webapppolimusicv1_asp` (74 archivos) y **ASP clásico sí
funcionaba** (`default.asp` devolvía 302), pero:
- Casi todas las páginas devolvían **HTTP 500**.
- `default.asp` redirigía a `/login.asp` en lugar de
  `/webapppolimusicv1_asp/login.asp` (el "error de path" que vio el usuario).
- Además se copiaron al destino `tools/`, `.workbuddy-ai/`, el `.sql` y el `.zip`
  que debían haberse excluido.

## Cómo se diagnosticó
1. Mapa de códigos HTTP de las 41 páginas: 500 solo en las que incluyen
   `includes/sha1.asp` o `includes/ui.asp`; `default.asp` (que no los incluye)
   funcionaba. `placeholder.asp` (sin includes) daba 200.
2. IIS Express **no sirve ASP clásico** en esta máquina (incluso un `test.asp`
   mínimo da 404) → descartado como banco de pruebas.
3. **Solución encontrada:** `MSScriptControl` (`msscript.ocx`, registrado solo
   en 32 bits) permite compilar VBScript de verdad desde PowerShell de 32 bits.
   Se creó `tools/vbscompile.py` + `tools/vbscheck.ps1`.

## Errores reales encontrados y corregidos
1. `includes/sha1.asp`: literales con sufijo de tipo de VBA (`4294967296#`,
   `2147483648#`, `16777216#`…). Compilan sueltos pero **rompen la condición
   `If d >= 2147483648# Then`** → "Se esperaba 'Then'". Sustituidos por `.0`.
2. `includes/ui.asp`: `Dim sql, sTop` → **`sTop` es inválido** porque en
   minúsculas es la palabra reservada `stop`. Renombrado a `sLimit`.
   Se validaron los 196 identificadores declarados del proyecto: ninguno más
   es inválido.
3. `includes/util.asp`: `AppBase()` usaba `APPL_MD_PATH`, que devuelve `/`
   cuando la carpeta es una subcarpeta del sitio y no una aplicación IIS.
   Ahora se deduce de `SCRIPT_NAME` (directorio de la página en ejecución).
   `AppPhysRoot()` usa `Server.MapPath(AppBase())` con respaldo.

## Estado
- **60 archivos compilados con el motor real: 0 errores de compilación.**
- `vbslint`, `vbscallcheck`, `htmlcheck`, `sha1_check` y `node --check`: todo OK.
- `deploy.ps1` reescrito: copia explícita (sin robocopy), limpieza de restos en
  el destino, `scriptErrorSentToBrowser=true` y verificación HTTP de 4 URLs.
- `desplegar.bat` ahora hace `cd /d "%~dp0"` y muestra el código de salida.

# 2026-10-15 (noche) — Segundo intento de despliegue: fallo de rutas

## Síntoma
```
==> Comprobando el entorno
[OK] IIS activo (servicio W3SVC: Running).
deploy.ps1 : No se puede enlazar el argumento con el parámetro 'Path'
             porque es una cadena vacía.
ATENCION: el despliegue termino con codigo 1.
```
Este era **el error de "path"** que el usuario mencionó desde el principio.

## Causa
`$PSScriptRoot` llegaba **vacío** al evaluarse el valor por omisión del
parámetro:
```powershell
param([string]$Source = $PSScriptRoot, ...)   # <-- $Source = ''
```
Al invocar el script desde un `.bat` elevado con `-File`, el bloque `param()`
puede evaluarse antes de que `$PSScriptRoot` esté disponible. Con `$Source`
vacío, la primera instrucción que lo usa (`Test-Path $Source`) falla con
`ParameterBindingValidationException` sobre el parámetro `Path`.

Nota: `$env:windir` y `$env:TEMP` sí estaban definidos (las líneas
`Join-Path` del inicio del script funcionaron), lo que confirma que el único
valor vacío era `$Source`.

## Corrección
1. `param([string]$Source = '', [string]$Target = '', [string]$SiteName = '')`
   y resolución **en el cuerpo** del script, con cadena de respaldos:
   `$PSScriptRoot` → `$MyInvocation.MyCommand.Path` →
   `$MyInvocation.MyCommand.Definition` → `(Get-Location).Path`.
2. `Resolve-Path -LiteralPath` + `throw` con mensaje claro si no se resuelve.
3. `Test-Path` siempre con `-LiteralPath` y comprobando antes que no esté vacío.
4. Bloque `trap` que muestra un resumen legible en lugar del volcado de
   excepción de PowerShell, y sale con código 1.
5. `desplegar.bat` ahora pasa `-Source "%~dp0."` de forma explícita y hace
   `cd /d "%~dp0"`.
6. Se imprime la carpeta del script, el origen y el destino al comenzar.

## Corrección adicional importante
El script borraba `assets\` antes de copiar (`Remove-Item -Recurse`), lo que
**habría eliminado los MP3 e imágenes subidos desde el panel**. Ahora se copia
el contenido en **modo combinación** (`Copy-Item "$src\*" -Destination $dst
-Recurse -Force`), sin borrar el destino.
